## 0. 站点定性与文案总原则

- **站点类型**：工具站（在线代码评测台）。红线：**工具本体（题目列表）放首屏、零营销区块**；隐私声明必须写清：**本机判题、数据不出机**。
- **目标访客**：本机做算法练习 / 教学演示的编程学习者与讲师。场景：写一段 C++ 代码，想立刻看到真实编译运行 + 逐用例判定反馈。
- **核心转化动作**（唯一）：**完成一次代码提交并看到逐用例判定结果与得分横幅**。答不上「它服务这个动作吗」的区块删掉。
- **文案纪律**：
  1. 不用「专业 / 强大 / 便捷 / 高效」这类形容词，改成数字或具体动作（不说「快速判题」，说「提交后逐用例返回判定，每个用例标注耗时毫秒数」）。
  2. 按钮全部用动词短语，不用「提交」「了解更多」。
  3. 判定提示语与 requirements.md 第七节判定表逐字一致；错误码前端提示与 spec 第 5.2 节逐字一致。
  4. 得分横幅固定格式 `通过 4/4 · 通过率 100% · 得分 100/100`，两种模式都用同一句式。

- **title**：`判定结果 · {题名} | CodeJudge`（例：`判定结果 · 运费计算 | CodeJudge`）
- **description**：`查看本次提交的逐用例判定：耗时、权重、差异行号，以及 CE 编译输出与 RE 信号提示。得分横幅给出通过率与得分。`
- **H1**：`判定结果：{最终判定}`（例：`判定结果：答案正确`；徽章仍显示 `AC`/`WA` 等代码，H1 用中文全称）
- **主词**：判题结果
- **长尾词**：AC WA TLE 判定、PE 空白差异、编译错误怎么看、判题提示

**呈现说明**：提交响应（POST /api/submissions）同步返回全量判定结果，本页一次渲染完成——得分横幅、逐用例表格、CE/RE 面板、源码回显都来自同一次响应，不需要二次查询。

#### 区块 0：提交信息行（横幅上方小字）

`提交 {sid} · {created_at} · 本次计分模式 {mode}`

- `{mode}` 显示中文：`OI（按权重计分）` / `ACM（全对记分）`；若本次覆盖了题目默认，追加标注 `（已覆盖题目默认 {contest_type}）`
- `{sid}` 格式即 spec：`YYYYMMDD-HHMMSS-<pid>-<4位hex>`

#### 区块 1：得分横幅（信息层级：结果一眼可见；格式固定不可改字）

横幅主文案（等宽字体，一整行）：

`通过 4/4 · 通过率 100% · 得分 100/100`

（绑定 `通过 {passed}/{total} · 通过率 {rate}% · 得分 {score}/{max_score}`；`pass_rate` 0–1 保留 4 位小数，展示时换算百分比）

模式补充行（横幅下方小字，按 mode 与结果二选一）：

- OI：`OI 模式：按通过用例的权重折算得分。`
- ACM 全 AC：`ACM 模式：全部用例通过，记满分。`
- ACM 非全 AC：`ACM 模式：未全对记 0 分。加权部分得分 {partial_score}，仅供参考。`（横幅里得分仍显示 `0/100`）

#### 区块 2：逐用例判定表格（信息层级：用例 → 判定 → 耗时 → 权重 → 提示）

表头（列名固定）：`用例 | 判定 | 耗时 | 权重 | 提示`

示例行：

| 用例 | 判定 | 耗时 | 权重 | 提示 |
|---|---|---|---|---|
| 1.in | AC | 12ms | 25 | `—` |
| 2.in | WA | 15ms | 25 | 第 3 行不一致：期望 '42'，实际 '41' |
| 3.in | TLE | 1000ms | 25 | 超时（限时 1000ms） |
| 4.in | RE | 8ms | 25 | SIGSEGV 段错误（空指针/越界） |

- 判定列用彩色徽章（`VerdictBadge`）；AC 的 `message` 为空时显示 `—`。
- `stderr_tail` 折叠展示：展开按钮 `看 stderr` / `收起 stderr`。
- 行可展开期望/实际输出对比（若引擎提供）：`看输出对比` / `收起对比`，差异行高亮。

#### 区块 3：CE 专属——编译输出面板（build_log）

- 标题：`编译器输出（末 200 行）`
- 说明行：`只显示末 200 行；完整输出已写入报告 JSON 的 build_log 字段。`
- 首条含 `error:` 的行：左侧红色色条 + 加粗；其余行等宽灰字、滚动块。
- 构建超时（60s）判 CE 时追加提示：`构建超过 60 秒被中止。检查模板递归或宏展开。`
- 折叠按钮：`展开编译输出` / `收起编译输出`。

#### 区块 4：RE 专属——运行错误面板

- 标题：`程序异常退出`
- 正文结构：`信号翻译`（一句，见第 4 节信号表）+ `stderr 末 2KB`（等宽块 + 按钮 `复制 stderr`）。
- Windows 降级文案（signal 为 null 时）：`进程非 0 退出码（exit code {N}）：Windows 下不细分信号，请看 stderr 定位。`

#### 区块 5：提交源码回显（可折叠）

- 标题：`本次提交源码（{files.length} 个文件）`
- 默认折叠，按钮 `展开源码` / `收起源码`；每个文件一节，文件名 + 等宽代码块 + `复制` 按钮。
- 单文件提交也包成 1 项显示（对应 `files` 字段）。

#### 区块 6：动作条（信息层级：改代码 → 再看记录）

- 主按钮：`返回题目改代码` → 跳转 `/problems/:pid`（编辑器保留上次源码）

### 页面 5：关于 / 使用说明 `/about`

- **title**：`使用说明 · 判定规则与本地运行 | CodeJudge`
- **description**：`从安装命令到看懂七种判定：判题流水线、ACM 与 OI 计分区别、CE 编译输出与 RE 信号说明，一页讲完。`

#### 区块 1：使用流程三步（信息层级：动作顺序，每步一句话 + 一个结果）

1. `选题` —— 在题目列表点卡片，进详情看题面、样例与限制摘要。
2. `写码并提交` —— 在等宽编辑区写代码（已预填 main 骨架），点「提交判题」。
3. `看结果` —— 得分横幅 + 逐用例表格，每行标注判定、耗时、权重与差异提示；不满意点「返回题目改代码」再来一发。

#### 区块 2：判定含义表（锚点 `#verdicts`，信息层级：判定 → 含义 → 怎么修）

完整表格见本文档第 4 节，此页直接渲染该表；每个判定行可展开帮助文案。

#### 区块 3：ACM / OI 计分说明（信息层级：先说结论再说例子）

- `OI`：通过哪个用例就拿哪个的权重分。得分 = Σ 通过权重 / Σ 总权重 × 满分。适合练题看进度。
- `ACM`：全部用例 AC 才记满分，否则记 0；表格里的加权部分得分（partial_score）只作参考。适合模拟赛。
- 提交时可覆盖题目默认模式（详情页「计分模式」单选）。
- 两种模式的得分横幅句式相同：`通过 4/4 · 通过率 100% · 得分 100/100`。

#### 区块 4：CLI 常用命令（锚点 `#cli`，信息层级：命令 → 作用）

命令块（等宽 + 按钮 `复制命令`）：

```bash
python judge.py list                 # 列出 P1–P6 与用例（权重/时限/备注）
python judge.py run P1 examples/P1_ac.cpp    # 评测单个提交
python judge.py import-samples exercise/P1-shipping.md   # 从题面抽取样例
```

| 判定 | 中文全称 | 触发条件 | 用户可见提示语（逐用例表格「提示」列 = message 字段） | 帮助文案（点击判定徽章展开） |
|---|---|---|---|---|
| `AC` | 答案正确 | 逐字符相等（trim 模式去掉末尾空行） | `—`（message 为空时统一显示破折号） | 输出与标准答案逐字符一致（trim 模式忽略末尾多余空行）。ACM 模式下全部用例 AC 才记满分；OI 模式按通过用例的权重折算得分。 |
| `PE` | 格式错误 | token 相等但文本不等 | `仅空白差异（PE）：内容相同但换行/空格不一致` | 内容对了，空格或换行不对。对照样例检查行尾空格、行数，以及是否多打了空格。 |
| `WA` | 答案错误 | 首个不一致行 | `第 i 行不一致：期望 '…'，实际 '…'`；行数不一致时：`行数不一致：期望 X 行，实际 Y 行` | 输出与标准答案不一致。看提示里的行号，用本地 diff 对比你的输出与样例输出。 |
| `TLE` | 超出时间限制 | 墙钟 > 1.5× 时限 或 CPU 时间 > 时限 | `超时（限时 Nms）` | 程序超过时限被强制终止。常见原因：算法复杂度过高、死循环、cin/cout 未关同步。 |
| `RE` | 运行时错误 | `exit_code < 0` 且信号可翻译 | 信号翻译短句（如 `SIGSEGV 段错误（空指针/越界）`） | 程序异常退出。按信号提示查空指针、越界、除零；Windows 下若只见「进程非 0 退出码」，看 stderr 末尾定位。 |
| `CE` | 编译错误 | 构建非 0 退出 / 构建超时 60s | `编译失败，展开查看编译器输出` | 编译没通过。展开「编译器输出（末 200 行）」，从第一条 `error:` 开始改。 |
| `SE` | 系统错误 | 基础设施异常（题目/用例缺失、缺 `.out`、报告写入失败等），对应 CLI 返回码 2 / `status=failed` | `评测器自身异常，本次提交未完成判定` | 这不是代码的判定结果。检查 `problems/<id>/` 目录与 `tests/` 是否完整、`reports/` 是否可写，修复后重新提交。 |

### RE 信号翻译说明（面板正文，原文照用 verdict.py 的 SIGNAL_MSG）

| 信号 | 翻译文案 |
|---|---|
| SIGSEGV | `段错误（SIGSEGV）：非法内存访问——常见于空指针解引用或数组越界` |
| SIGFPE | `算术异常（SIGFPE）：除零或整数溢出` |
| SIGABRT | `程序中止（SIGABRT）：assert 失败或显式 abort()` |
| SIGBUS | `总线错误（SIGBUS）：地址未对齐 / 非法映射` |
| SIGKILL | `被强制终止（SIGKILL）：疑似内存超限或被系统回收` |
| SIGXCPU | `CPU 时间超限（SIGXCPU）` |

- 面板附加：`stderr 末 2KB`（等宽块 + `复制 stderr` 按钮）。
- **Windows 降级**（spec 第 10 节已知约束）：信号不可用时 `signal` 为 null，显示 `进程非 0 退出码（exit code {N}）：Windows 下不细分信号，请看 stderr 定位。`

### CE 编译器输出展示说明

- 面板标题：`编译器输出（末 200 行）`（数据字段 `build_log`）
- 说明行：`只显示末 200 行；完整输出已写入报告 JSON 的 build_log 字段。`
- 首条含 `error:` 的行：左侧红色色条 + 加粗；其余行等宽灰字、等宽滚动块。
- 构建超时（默认 60s）也判 CE，提示行追加：`构建超过 60 秒被中止。检查模板递归或宏展开。`
- 折叠按钮：`展开编译输出` / `收起编译输出`。

### 得分横幅（全站固定，两模式同句式）

```
通过 4/4 · 通过率 100% · 得分 100/100
```

- 绑定：`通过 {passed}/{total} · 通过率 {rate}% · 得分 {score}/{max_score}`（pass_rate 0–1 保留 4 位小数）。
- OI：`score = Σ 通过权重 / Σ 总权重 × 满分`，横幅显示实际得分（例：`通过 1/4 · 通过率 25% · 得分 25/100`）。
- ACM 全 AC：`通过 4/4 · 通过率 100% · 得分 100/100`，补一行 `ACM 模式：全部用例通过，记满分。`
- ACM 非全 AC：横幅 `通过 1/4 · 通过率 25% · 得分 0/100`，补一行 `ACM 模式：未全对记 0 分。加权部分得分 {partial_score}，仅供参考。`
- `partial_score` 两种模式都返回：OI 时与 `score` 相同（不另显示）；ACM 时才显示「仅供参考」行。

## 5. 错误码文案与空状态 / 边界文案

### 5.1 错误码前端提示（8 个，逐字用 spec 5.2 冻结文案）

**统一语气**：短句、中文、先说「发生了什么」再说「下一步做什么」；不用感叹号、不用「抱歉」开头、不用表情；句式统一为「陈述 + 祈使收尾（请…）」。

| code | HTTP | 触发场景 | 前端提示（逐字使用） | 可选补充行（陈述事实，不与主提示抢戏） |
|---|---|---|---|---|
| `VALIDATION_ERROR` | 400 | 字段缺失/类型不符/`source_code` 与 `files` 未恰好给其一/文件名非法 | `提交内容不合法，请检查后重试` | `文件名仅限字母、数字、_ . -，最长 64 字符` |
| `PROBLEM_NOT_FOUND` | 404 | `pid` 不在 P1–P6 | `题目不存在` | `回到题目列表选一道题` |
| `SUBMISSION_NOT_FOUND` | 404 | `sid` 无对应报告 | `找不到该次提交` | `可能已被清理，回提交历史看看` |
| `PAYLOAD_TOO_LARGE` | 413 | 单文件 > 65536 字符 或 files 总量 > 262144 字符 或 files > 20 项 | `代码太长，请精简后重试` | `单文件上限 65536 字符，最多 20 个文件` |
| `JUDGE_TIMEOUT` | 408 | 整单判题超过 120s 硬上限 | `判题超时，请检查死循环后重试` | `整单判题上限 120 秒` |
| `JUDGE_BUSY` | 429 | 已有一次判题在执行 | `判题进行中，请稍候重试` | `同时只判一单，完成后可再提交` |
| `ENGINE_UNAVAILABLE` | 503 | `g++`/`make` 不在 PATH 或引擎初始化失败 | `判题引擎不可用，请检查本机编译环境` | `确认 g++ 与 make 已安装并加入 PATH` |
| `INTERNAL_ERROR` | 500 | 其他未预期异常 | `服务异常，请重试` | `反复出现请查看本机控制台日志` |

- **网络断开兜底**（fetch 失败，无错误体）：`连不上判题服务，请确认本机后端已启动后刷新页面`。
- 错误条（ErrorBar）构成：`主提示（粗体） + 补充行（灰字，可省） + 动作按钮`。动作按钮按场景取：`回到题目列表` / `刷新页面` / `返回改代码`。
- **示例**（错误条完整形态）：
  - 提交时 429：`判题进行中，请稍候重试` + `同时只判一单，完成后可再提交` + 按钮 `刷新状态`
  - 打开详情时 404：`题目不存在` + `回到题目列表选一道题` + 按钮 `回到题目列表`

### Δ1-6 About 新增小节「账号与云同步」（锚点 `#account`）

> 插入位置：既有区块 7「本地处理声明」之后、区块 8「返回入口」之前。

#### 区块：账号与云同步

1. **注册与登录**：邮箱 + 密码（至少 8 位）注册，或 GitHub 一键登录。登录后提交判题，历史入你的账号，换机登录即见。
2. **GitHub OAuth 说明**：点「使用 GitHub 登录」跳转 GitHub 授权页，同意授权后自动回本站。首次使用即自动创建账号，不需要再填密码；GitHub 账号邮箱需完成验证，未验证的提示见 Δ1-7。
3. **数据归属**：云端历史（时间、题目、判定、得分与报告明细）随账号走，按账号隔离，其他账号看不到你的记录。本机 `reports/` 目录始终保留每次判题的原始报告文件；删除账号即删除其云端历史。
4. **隐私声明更新（双模式表述）**：
   - 本地模式（未配置 Supabase）：判题与历史都在本机，数据不出机。
   - 云模式（已登录）：判题仍在本机执行，源码不上传第三方；**入库的只有判题历史**（含提交源码回显，便于换机回看），存入 Supabase，按账号隔离。源码不用于训练、不对外共享。
   - 页脚声明行相应替换为：`本地模式数据不出机；云模式仅判题历史入你的账号。`
   - 本地匿名历史与云端历史互不迁移：换机或清理浏览器后，本地匿名历史不可恢复；云端历史随账号保留。
5. 返回入口沿用：`回题目列表做题` → `/`。

### Δ1-7 认证与授权错误码中文提示（11 条）

统一语气：与既有错误条一致（短句、陈述为主、必要时「请…」收尾；不用感叹号、不以「抱歉」开头）。错误条构成同 5.1：主提示（粗体）+ 补充行（灰字，可省）+ 动作按钮。

| code | 触发场景 | 前端提示 | 可选补充行 / 动作 |
|---|---|---|---|
| `invalid_credentials` | 邮箱或密码不对 | `邮箱或密码不正确` | 补充行 `请检查大小写后重试` |
| `email_not_confirmed` | 未验证邮箱就登录 | `邮箱还没验证，请先打开验证邮件里的链接` | 补充行 `没收到邮件请检查垃圾箱` |
| `user_already_exists` | 注册已存在的邮箱 | `该邮箱已注册，请直接登录` | 动作链接 `去登录` |
| `weak_password` | 密码不合强度要求 | `密码至少 8 位，请加长后重试` | — |
| `over_email_send_rate_limit` | 验证 / 重置邮件发太勤 | `邮件发送过于频繁，请稍后再试` | 补充行 `10 分钟后再试一次` |
| `provider_email_needs_verification` | GitHub 邮箱未验证 | `GitHub 账号邮箱未验证` | 补充行 `请到 GitHub 设置里验证邮箱后重试` |
| `over_request_rate_limit` | 接口请求过频 | `请求过于频繁，请稍后再试` | — |
| `signup_disabled` | 后台关闭注册 | `注册当前未开放，请联系管理员` | — |
| `session_expired` | 登录态过期 / 刷新失败 | `登录状态已过期，请重新登录` | 动作按钮 `去登录` |
| `email_address_invalid` | 服务端判邮箱非法 | `邮箱格式不正确` | 补充行 `请检查后重试` |
| `UNAUTHORIZED` | 带了登录态但校验失败 / 过期（统一错误体枚举，Δ1 新增，HTTP 401） | `请先登录（登录状态可能已过期）` | 动作按钮 `去登录` |

**UNAUTHORIZED 与拦截提示的使用场景区分**：拦截提示「登录后可提交判题并云同步历史。」= 未登录状态点「提交判题」的前置拦截；`UNAUTHORIZED` = 请求携带了登录态但服务端校验失败 / 已过期（如会话失效后提交）。两者不混用。
