# P32 猴子分桃

> 难度：中等 · 计分：ACM · **C 语言题**，单文件提交（main.c） · 构建：gcc -O2 -std=c11 · 时限 2000ms / 256MB
> 题源：情境拓展 ·《趣味数学及编程拓展》4.8.1 猴子分桃。本题题面自包含，无需查阅原卷。

## 题目背景

这是一道经典趣味数学题。海滩上有一堆桃子，n 只猴子依次来分。

第 1 只猴子来了，把桃子平均分成 n 份，发现多出 1 个，于是扔掉这 1 个，拿走其中 1 份，把剩下的 n-1 份合在一起；第 2 只猴子对剩下的桃子做同样的操作……直到第 n 只猴子也这样做完。最后 n 只猴子一起回来，把剩下的桃子平均分成 n 份，**这次恰好分完，一个不多**。

求最初那堆桃子最少有多少个。

## 输入格式

一行，一个整数 n（2 ≤ n ≤ 9），表示猴子的数量。

## 输出格式

一行，一个整数，表示满足条件的最小桃子总数。

## 样例输入

```
5
```

## 样例输出

```
3121
```

样例说明：5 只猴子时最少需要 3121 个桃子。依次为 3121 → 2496 → 1996 → 1596 → 1276 → 最后剩 1020 = 5×204，恰好分完。

## 样例输入 2

```
3
```

## 样例输出 2

```
25
```

## 样例输入 3

```
2
```

## 样例输出 3

```
11
```

## 数据范围

- 2 ≤ n ≤ 9

## 思路提示

从"最后剩下的桃子"反推更省时：最后剩下的数一定是 n 的倍数，设为 n×k（k 从 1 开始递增）。每只猴子操作前的数量 x 满足"操作后剩下 = (n-1)(x-1)/n"，反解得 x = 余数/(n-1)×n + 1，要求余数能被 n-1 整除。从 n×k 开始连续反推 n 次，若每步都能整除，得到的就是最初的桃子数；取最小的 k 即为答案。

## 常见错误

1. 正向枚举初始桃子数，n 较大时数值增长极快，不可行。
2. 反推时漏掉整除判断，产生非整数结果。
3. 把"最后恰好分完"误写成"最后仍多出 1 个"，起点会错，答案不对。
