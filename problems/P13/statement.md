# P13 共同空闲

> 难度：中等 · 多文件 make 工程 · 构建：`make` → `freeslot` · 时限 2000ms / 256MB

## 题目背景

自习室要排一次"两人共同自习"的时间。一天被切成 `0` 到 `D` 共 D+1 个**整数分钟**，每个人给出自己已经被占用的时段。

时段的写法是闭区间 `a-b`，表示第 a、b 分钟（含两端）都被占用。一行的多个时段用英文逗号分隔，**允许乱序、允许重叠、允许重复**；如果这个人整天空闲，这一行只有一个 `-`。

两个人都没被占用的分钟，就是可以一起自习的时间。请把这些分钟按**连续的一段一段**合并成闭区间，升序输出。

注意这是**整数分钟**语义：某人占用 `1-3`，那么第 4 分钟就是空闲的第一分钟，空闲段从 `4` 开始，不是从 `3` 开始。

本题考查：区间归并（排序 + 一次扫描）、求补集（空闲段）、两组有序区间的双指针求交、输出格式控制，以及把逻辑拆成 `.h` / `.cpp` 的多文件工程习惯。

## 输入格式

- 第 1 行一个整数 `D`（0 ≤ D ≤ 10⁹），表示这一天的时间轴是 `0..D`。
- 第 2 行：甲的占用时段，形如 `1-3,5-6`，逗号分隔、逗号两侧**没有空格**；整天空闲时这一行是 `-`。
- 第 3 行：乙的占用时段，格式同上。

## 输出格式

- 一行。按升序输出所有共同的空闲段，段与段之间用 `, `（逗号 + 一个空格）分隔，每段写作 `l-r`（单点写作 `l-l`，例如 `0-0`）。
- 如果两人没有任何共同空闲的分钟，输出正好四个大写字母 `NULL`。

## 提交要求

- 提交**多文件工程**：至少包含 `Makefile` 与源码（建议按 `slot.h` 声明 / `slot.cpp` 实现 / `main.cpp` 主程序 三份拆分）。
- 平台在提交目录执行 `make freeslot`，因此 Makefile 里必须有名为 `freeslot` 的目标，并产出可执行文件 `freeslot`。
- 只从标准输入读、只往标准输出写；调试信息不得写入 stdout。

## 样例说明

- **样例 1**：甲占 1-3、5-6，甲的整数分钟空闲是 `0`、`4`、`7..10`；乙占 2-4，乙的空闲是 `0-1`、`5-10`。两边都空的是 `0` 和 `7..10` → `0-0, 7-10`。第 4 分钟只有甲空、乙被占，不能算共同空闲。
- **样例 2**：两人整天空闲，全天 `0-5` 都是共同空闲；**注意不要输出成 `0--1` 或空行**。
- **样例 3**：甲把 `0-8` 全占了，共同空闲集合为空 → `NULL`。
- **样例 4**：甲空闲 `3-5`、`8-9`、`11-12`；乙空闲 `0-0`、`2-5`、`8-12`；逐段求交得 `3-5`、`8-9`、`11-12`。
- **样例 5**：同样是先归并、再求交。甲 `1-3` 与 `3-4` 共享端点 3，归并成 `1-4`；乙的 `9-9` 与 `10-12` 中间不共享端点（9 和 10 是相邻的两个整数），保持两段。甲空闲 `0`、`9-20`；乙空闲 `0-8`、`13-20`；交集为 `0-0, 13-20`。

## 实现提示

**把问题拆成三步，每步只做一件事：**

1. **归并**：把每人的原始段按左端点升序（左端点相同再按右端点）排序，然后一次扫描合并——下一段的左端点 ≤ 当前段的右端点（共享端点也算接上）就延长当前段的右端点，否则另起一段。被包含的段（如 `2-3` 落在 `1-10` 里）只会让右端点保持不动，**绝不能把右端点改小**。
2. **求补**：在 `[0, D]` 上按归并结果扫一遍，维护"下一个可用分钟" `cursor`（初值 0）。遇到一段 `[l, r]`：若 `l > cursor`，说明 `[cursor, l-1]` 是空的；然后把 `cursor` 推到 `r + 1`。扫完后若 `cursor ≤ D`，尾巴 `[cursor, D]` 也是空的。
3. **求交**：两组空闲段都已升序且互不相交，用双指针走：取两段的重叠部分 `[max(l1,l2), min(r1,r2)]`，有重叠就收下；然后谁的右端点更小就谁先往后走一步。

**类的划分**（参考实现）：`Slot` 只装两个整数；`DayPlan` 负责"收段 → 归并 → 求补"，`intersect` 做成静态成员，`main.cpp` 只做输入解析与打印。头文件写声明、`.cpp` 写实现，`normalize()` 和 `freeWithin()` 不改变"逻辑上的日程"，后者声明成 `const` 成员函数。

**关键边界与易错点**：

- **闭区间不是左闭右开**：占用 `1-3` 之后，空闲从 `4` 开始（`r+1`），不是从 `3` 开始。
- **共享端点要合并**：`1-3` 与 `3-4` 是同一段连续占用（第 3 分钟被两人都算占用），归并成 `1-4`；但 `9-9` 与 `10-12` 是相邻的两段，合不合并都不影响空闲结果。
- **整天空闲的输入是 `-`**：不是空行、不是 `0-0`。用 `getline` 整行读入，并且要清掉行尾可能的 `\r`。
- **千万不能按分钟枚举**：D 可达 10⁹，必须只在段的端点上做运算。
- **`NULL` 是全大写**，且不能带多余的逗号或空格。

## 数据范围

- 0 ≤ D ≤ 10⁹
- 每行的时段数 ≤ 10⁵；任一时段满足 0 ≤ a ≤ b ≤ D
- 每行内的时段可能乱序、重叠、重复给出
- 共同空闲段数 ≤ 2×10⁵

## 常见错误

1. **把闭区间当左闭右开**：`r` 之后直接接 `r`，导致空闲段少一分钟（`1-3` 后面写成 `3-5` 而不是 `4-5`）。
2. **归并时右端点被改小**：遇到被包含的段写成 `right = r`，`1-10, 2-3` 会被缩成 `1-3`，后面全错。
3. **忘了排序就扫描**：输入允许乱序，直接扫会把 `5-6` 排到 `1-3` 前面，合并结果完全错乱。
4. **用 `cin >>` 读整行**：`1-3,5-6` 中间没有空格，`cin >>` 读不到分隔符，解析直接崩；必须 `getline` 读一行再按逗号切。
5. **双指针求交写成暴力配对**：两两比较是 O(n·m)，10 万段会超时；正确做法是每次移动右端点较小的那一段。
6. **输出分隔符不统一**：`1-2,3-4`（逗号后缺空格）、末尾多一个 `, `、或者用中文逗号，都会被判为格式错误。
7. **Makefile 目标名写错**：平台执行的是 `make freeslot`，目标写成 `all` 或 `main` 会直接判编译失败。
