# P14 密文算式

> 难度：困难 · 单文件提交（main.cpp） · 构建：g++ -O2 -std=c++17 · 时限 2000ms / 256MB

## 题目背景

一台老式计算器把每条算式都用"密钥 + 字符位移"存成了密文。它只认**前缀表达式**，操作数还是**指定进制**的整数。现在给你若干条密文记录，请把每条记录还原成算式、算出结果。

**明文长什么样**（解出来后就是这个样子）：

- 运算符不写符号，写成大写字母：`A` 是加、`S` 是减、`M` 是乘、`D` 是除；
- 操作数写成该进制的整数，可带前导负号，例如十进制下的 `-42`、八进制下的 `17`；
- 整行是合法前缀表达式，token 之间至少一个空格，行首、行中可能有连续多个空格。

**字符怎么加密**（对整行逐个字符，位置 `i` 从 0 开始，**空格也占位置**）：

- 先给字符编号：`a`..`z` 是 0..25，`A`..`Z` 是 26..51；
- 令 `shift = 编号(key[i mod |key|])`：
  - 字母：密文字符 = `编号((值 + shift) mod 52)` 对应的字母（大小写由编号落在哪一段决定）；
  - 数字：密文字符 = `'0' + (数字 + shift mod 10) mod 10`；
  - 空格、负号 `-`：**原样保留**，所以密文里的 token 边界和负号都还看得见。

解密就是同一套规则反过来：字母减 `shift`（`+52` 再取模，别让负数取余出错），数字减 `shift mod 10`（`+10` 再取模）。

考查：字符编码与取模、进制转换、用数组模拟栈逆序求值、浮点输出格式、多组数据。

## 输入格式

- 第 1 行一个整数 `T`，表示记录条数。
- 接下来每条记录**两行**：
  1. 一行两个 token：`B key`。`B` 是进制（2 ≤ B ≤ 10），`key` 是不含空格的大小写字母串（长度 1..20）。
  2. 一行密文：由空格分隔的若干 token，行首可能有空格。

## 输出格式

- 共 T 行，每行一个数：该记录的算式值，`固定小数点后 6 位`（例如 `42.000000`、`-0.125000`）。
- 除法是实数除法，不要写成整数除法。

## 提交要求

- 提交**单个源文件** `main.cpp`（C++），由平台执行 `g++ -O2 -std=c++17 -o {bin} {src}` 构建。
- 程序从标准输入读取数据、向标准输出写出结果；调试信息不得写入 stdout。

## 样例说明

- **样例 1**：`key = "ab"`，编号是 `a→0`、`b→1`，位置 `i mod 2` 轮流取 0、1。位置 0 的 `S` 位移 0 仍是 `S`；位置 2 的 `5` 位移 0 仍是 `5`；位置 3 的 `0` 位移 1 变成 `1`；位置 5 的 `8` 位移 1 变成 `9`。所以密文是 `S 51 9`，解出来 `S 50 8`，即 50 − 8 = **42**。
- **样例 2**：`B = 2`，`101` 是二进制 5，`11` 是二进制 3，`M` 是乘：5 × 3 = **15**。
- **样例 3**：解出 `D 1 3`，即 1 ÷ 3 = 0.3333…，输出六位小数 **0.333333**。若用整数除法会得到 0，直接错。
- **样例 4**：这一行**行首有两个空格、token 之间有连续空格**。位置 `i` 是按整行字符（含空格）数的，不是按 token 序号，也不是把空格压缩后再数。解出 `A M 2 3 S 10 4`，即 (2 × 3) + (10 − 4) = **12**。
- **样例 5**：`B = 8`，`17` 是八进制 15，`7` 是 7，15 × 7 = **105**。

## 实现提示

**按顺序拆成三步，每步都能单独验证：**

1. **解密一整行**：`for (i = 0; i < 密文长度; i++)`，先算 `shift = 编号(key[i % L])`，再按"字母 / 数字 / 其它"三路处理。字母用 52 取模、数字用 10 取模，`-` 和空格原样抄过去。**这一步不改变字符串长度**，所以位置 `i` 在密文和解文中是同一个下标。
2. **切 token**：解出来的仍是空格分隔的一行，`istringstream` 或手写扫描都行。单字符且是 `A`/`S`/`M`/`D` 的 token 当运算符，其余当操作数。
3. **逆序求值**：从**最后一个** token 往左扫。数字就按 `value = value * B + digit` 转成该进制的数（有负号先记下来）压栈；遇到运算符就连取两个数——**先取到的是左操作数**，算完把结果压回去。最后栈里剩的那一个数就是答案。

**为什么必须倒着扫**：前缀表达式的运算符写在两个操作数前面，从左往右读时还不知道操作数是多少；从右往左读，遇到运算符时它需要的两个结果都已经算好了。这就是"栈"最自然的用法。

**关键边界与易错点**：

- **位置要按整行算**：`i % |key|` 里的 `i` 是字符下标（空格占位），不是第几个 token。
- **负数取模**：`(值 - shift) % 52` 在 C++ 里可能得到负数，必须写 `((值 - shift) % 52 + 52) % 52`。
- **左右操作数不能反**：减法和除法尤其明显，`S 50 8` 是 50−8，不是 8−50。
- **栈要用数组，不要递归**：token 数可达 10 万，递归深度同样能到 5 万，递归写法会栈溢出崩溃。
- **用 double 求值**：全程 `long long` 会把除法截断。
- **输出格式**：`cout << fixed << setprecision(6)`；不要自己拼小数位数。

## 数据范围

- 1 ≤ T ≤ 10
- 2 ≤ B ≤ 10
- 1 ≤ |key| ≤ 20，`key` 只含大小写字母
- 每条记录的 token 数 ≤ 10⁵，密文行长度 ≤ 10⁶
- 操作数绝对值 ≤ 10⁶；中间结果与最终结果的绝对值 ≤ 10¹²，除数保证不为 0
- 保证解密后一定是合法前缀表达式

## 常见错误

1. **位置从 token 序号算**：把 `i` 当成"第几个 token"或"第几个非空格字符"，密钥错位，整行全乱。
2. **解数字时忘了 `+10`**：`(d - shift) % 10` 为负，得到非法字符。
3. **把 `A` 当成操作数**：解出的 `A` 是加号，只有当 token 是**单个字符**时才可能是运算符；`-12` 里的 `-` 不是运算符。
4. **从左往右求值**：前缀表达式不能正序算，必须倒序 + 栈。
5. **左右取反**：先 `pop` 的是左操作数，写成 `right OP left` 会让所有减法、除法结果反过来。
6. **递归求值**：5 万层嵌套直接段错误，判 RE。
7. **进制转换只对第一个数字生效**：`value = value * B + digit` 要逐位乘，别只取最后一位。
8. **输出小数位数不固定**：`cout << 结果` 会输出 `42` 而不是 `42.000000`，必须 `fixed` + `setprecision(6)`。
