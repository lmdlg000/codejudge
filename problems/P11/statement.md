# P11 工程排程

> 难度：困难 · 多文件 make 工程（恰好 6 个文件） · 构建：`make` → `scheduler` · 时限 2000ms / 256MB

## 题目背景

某工程项目包含 n 个任务，任务 i 的工期为 d_i 天。任务之间存在 m 条依赖关系：依赖 u → v 表示任务 u 必须完成后，任务 v 才能开始。工地有无限多台并行机器，任意任务在其全部前驱任务完成的那一刻即可立即开工，不受其他未完成任务影响。

项目管理者需要评估两件事：

1. 整个工程的最短完工时间（即最后一个任务完成的最早时刻）；
2. 一种字典序最小的合法任务执行顺序（拓扑序），用于排班公示。

若依赖关系成环（任务互相等待），则工程无法完成。

## 输入格式

第一行两个整数 n 和 m，表示任务数与依赖关系数。

第二行 n 个正整数 d_1 d_2 … d_n，表示每个任务的工期。

接下来 m 行，每行两个整数 u v（1 ≤ u, v ≤ n），表示一条依赖：任务 u 完成后任务 v 才能开始。

## 输出格式

若依赖成环，输出一行 `-1`。

否则输出两行：

- 第一行一个整数，表示最短完工时间；
- 第二行 n 个整数，表示字典序最小的合法拓扑序，编号之间用一个空格分隔，行末无多余空格。


## 提交要求（多文件 make 工程）

多文件提交**恰好包含这 6 个文件**（文件名固定）：

| 文件 | 内容 |
| --- | --- |
| `topo.h` / `topo.C` | 建图、入度计算、最小堆拓扑排序（就绪集每次取编号最小者）、环检测 |
| `critical.h` / `critical.C` | 关键路径动态规划，求最短完工时间（最长加权路径） |
| `main.C` | 主程序：读入数据、调用上述模块、按格式输出 |
| `makefile` | 构建规则（见下） |

- **`.h` 只放声明 + 头文件保护宏**（`#ifndef/#define/#endif`），实现全部放 `.C`；
- 每个 `.C` **首行 `#include` 对应的 `.h`**（如 `topo.C` 首行 `#include "topo.h"`）；
- 允许使用 STL 容器与 `<queue>`、`<algorithm>` 等（本题考算法组织而非裸字符处理）；
- `makefile` 要求：`TARGET = scheduler`、`all` 生成 `scheduler`、`clean` 删除 `.o` 与 `scheduler`、`CXX = g++`、`CXXFLAGS = -std=c++20 -O2 -w -Wall`、每个 `.o` 写清依赖的 `.h`、**配方行以 Tab 缩进**（不是空格）、**不写死绝对路径**。参考模板（`$(CXX)`、`rm` 行前是 Tab）：

```makefile
CXX = g++
CXXFLAGS = -std=c++20 -O2 -w -Wall
OBJ = main.o topo.o critical.o
TARGET = scheduler

all: $(TARGET)

$(TARGET): $(OBJ)
	$(CXX) $(CXXFLAGS) -o $(TARGET) $(OBJ)

main.o: main.C topo.h critical.h
	$(CXX) $(CXXFLAGS) -c main.C

topo.o: topo.C topo.h
	$(CXX) $(CXXFLAGS) -c topo.C

critical.o: critical.C critical.h topo.h
	$(CXX) $(CXXFLAGS) -c critical.C

clean:
	rm -f $(OBJ) $(TARGET)

.PHONY: all clean
```

变量名与 `.o` 列表可自行调整，但行为必须满足：`make` 生成 `scheduler`、`make clean` 清干净 `.o` 与可执行文件、每个 `.o` 依赖写全对应的 `.h`。

算法复杂度需达到 O((n + m) log n)。

## 样例输入
```text
4 3
3 2 4 1
1 2
1 3
3 4
```

## 样例输出
```text
8
1 2 3 4
```

## 样例说明

任务 1 无前驱，工期 3，在 [0, 3] 执行；任务 2 依赖 1，在 [3, 5] 执行；任务 3 依赖 1，在 [3, 7] 执行；任务 4 依赖 3，在 [7, 8] 执行。工程在时刻 8 完工，故最短完工时间为 8。

就绪集每次取编号最小者得到的拓扑序为 1 2 3 4，是字典序最小的合法拓扑序。

## 实现提示

本题两问共享一次拓扑排序，正好对应 `topo.*`（排序 + 环检测）与 `critical.*`（关键路径 DP）两个模块；**拓扑序可以直接在 DP 过程中复用**。

**① 最小堆拓扑排序（字典序最小，6 步）**

1. 用邻接表存依赖边 `u → v`（u 完成后 v 才能开始），同时统计每个结点的**入度** `indeg[v]`；
2. 把所有 `indeg == 0` 的结点压入**最小堆**（`priority_queue<int, vector<int>, greater<int>>`——就绪集每次取编号最小者）；
3. 堆非空时弹出堆顶 `u`，记入拓扑序；`out_cnt++`；
4. 枚举 `u` 的每条出边 `u → v`：`indeg[v]--`，若减到 0 则把 `v` 压堆；
5. 重复 3~4 直到堆空；**若 `out_cnt < n`，说明有环**——直接输出 `-1` 结束；
6. 得到的拓扑序即字典序最小的合法执行顺序（注意第二行 n 个编号之间**一个空格**、行末无多余空格）。

**② 最短完工时间 = 最长加权路径（关键路径 DP，4 步）**

7. 按上面得到的拓扑序依次处理每个结点：`finish[u]` 表示任务 u 的**完成时刻**；
8. 转移公式：**`finish[v] = max(finish[u] + d_v)`**（对 v 的所有前驱 u；无前驱则 `finish[v] = d_v`）——含义是 v 必须等**全部**前驱完成才能开工，故开工时刻 = 前驱完成时刻的最大值，完成时刻 = 开工 + 自己的工期 `d_v`；
9. **注意工期加在被指向的任务上**：`finish[v]` 里加的是 **`d_v`**（v 自己的工期），不是 `d_u`、也不是边权（本题边无权，工期挂在结点上）；
10. 答案 = **所有结点 finish 的最大值**（不限于某个"汇点"，图可能不连通、可能有多个终点）。

**关键边界与易错点**：

- **"最短完工"是"最长"路径**：无限并行机器下，完工时间由**最慢的一条依赖链**决定——DP 要取 `max`，写成 `min` 或普通最短路就错了；
- **拓扑序必须是最小堆的**：用普通 `queue` 只能得到"某个"合法拓扑序，字典序不保证最小——就绪集用 `greater<int>` 的 `priority_queue`；
- **DP 与拓扑序共用一次排序**：不必跑两遍拓扑——按最小堆拓扑序推进 DP 即可，DP 依赖前驱已完成，拓扑序天然保证；
- **环检测口径**：输出结点数少于 n 即有环，**只输出一行 `-1`**，不要输出后面两行；
- **`d_i` 最大 10^9、链长可达 n**：完工时间可达 10^14，DP 数组用 `long long`；
- **输出格式**：拓扑序编号之间恰好一个空格，行末无多余空格。

## 数据范围

- 1 ≤ n ≤ 100000
- 0 ≤ m ≤ 200000
- 1 ≤ d_i ≤ 10^9
- 允许图不连通；输入无重边；可能有环
- 时间限制 2000 ms，内存限制 256 MB

## 常见错误

1. **把"最短完工"写成最短路**：DP 取 `min` 或跑 Dijkstra——无限并行机器下完工时间由最慢依赖链决定，必须是**最长加权路径**（`finish[v] = max(finish[u] + d_v)`）。
2. **拓扑排序用普通队列**：`queue` 只保证"某个"合法拓扑序，字典序不最小——就绪集要用**最小堆** `priority_queue<int, vector<int>, greater<int>>`。
3. **工期加错位置**：`finish[v] = max(finish[u] + d_u)` 或给边加权——工期挂在**结点**上，转移时加的是 **`d_v`**（v 自己的工期）。
4. **忘了等全部前驱**：`finish[v]` 只取了"某一个"前驱的完成时刻——v 要等**所有**前驱完成才能开工，应对全部前驱取 `max`。
5. **环检测漏判或输出错**：拓扑排序后没比对输出结点数与 n、或有环时还继续输出两行——`out_cnt < n` 即有环，**只输出一行 `-1`**。
6. **答案只取"汇点"**：只算入度为 0 出发到出度为 0 结点的 finish——图可不连通、可有多个终点，答案是**全部结点 finish 的最大值**。
7. **`int` 存完工时间**：d_i 最大 10^9、链长可达 n，finish 可达 10^14——DP 数组用 `long long`，`int` 会溢出。
8. **拓扑序输出格式错**：编号之间多个空格或行末带空格——恰好一个空格分隔，行末无多余空格。
