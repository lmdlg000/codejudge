# P17 弹幕射击

> 难度：困难 · 多文件 make 工程 · 构建：`make` → `shooter` · 时限 2000ms / 256MB

## 题目背景

Session7 的课堂程序是一个 ncurses 射击游戏：`Gui` 封装终端，`Game` 管着一个 `Player` 和一个 `list<Bullet*>`，左右键移动、空格发射，子弹飞出屏幕就从链表里删掉。本题是它的**增强版**，改了三件事：

1. **把“屏幕”换成标准输出**：ncurses 必须有真实的交互终端（TTY）才能工作，而判题机的标准输入输出是**重定向的管道**，没有 TTY，原版程序在那儿起不来。所以本题不用 ncurses，改成"每帧把画面按行打印到 stdout"——同一套游戏逻辑，判题机能逐字符对拍，你在本地用 `./shooter < 1.in` 就能测，**不需要开终端窗口、也不需要装 ncurses**；
2. **加上真正的敌人**：坦克 `T` 会左右移动、定期投弹 `*`，被砸中要掉命；
3. **加上节奏**：开火有冷却、场上子弹有上限、坦克打掉后会重生并给奖励分。

这是**多文件工程题**：请按「实体基类 + 若干派生类 + 游戏控制类」拆分，用基类指针 + 虚函数统一驱动所有对象——正是第 10 讲「多态」的直接应用。

## 棋盘与坐标

- 棋盘共 H 行 W 列；**行号 0 在最上面**，向下递增；列号 0 在最左边。
- 每格输出一个字符，空地是空格。

| 字符 | 含义 |
|---|---|
| `M` | 玩家 |
| `T` | 坦克 |
| `^` | 子弹（向上飞） |
| `*` | 炸弹（向下落） |

## 初始局面

| 对象 | 初始状态 |
|---|---|
| 玩家 | `(H-2, W/2)`，生命 `LIVES = 3` |
| 坦克 | `(1, W/2)`，血量 `HP = 1`，方向**向右** |
| 子弹 / 炸弹 | 场上为空 |
| 计分 | `SCORE = 0`、`HITS = 0`、`KILLS = 0`、`TAKEN = 0` |
| 开火冷却 | `0` |

帧号从 **0** 开始编号。

## 每帧的处理顺序

每帧先读一个按键，然后**严格按下面 8 步执行**（顺序错一步，后面全错）：

1. **冷却递减**：若冷却 > 0，冷却减 1。
2. **玩家行动**：`a` 左移 1 列（不能 < 0）、`d` 右移 1 列（不能 ≥ W）、`s` 开火、`.` 不动。
   - 开火条件：冷却 == 0 **且** 场上子弹数 < **3**。
   - 满足则在 `(玩家行 - 1, 玩家列)` 生成一颗子弹，冷却置为 **3**；不满足则本帧不开火，冷却保持不变。
3. **子弹推进**：每颗子弹行号减 1。
   - 新位置与坦克**同行同列** → 命中：子弹消失、坦克 HP 减 1、`SCORE += 10`、`HITS += 1`。
   - 行号 < 0 → 飞出顶部，消失。
4. **击毁判定**：坦克 HP ≤ 0 → 坦克回到 `(1, W/2)`、HP 恢复 1、方向朝右，`SCORE += 50`、`KILLS += 1`。
5. **坦克移动**：**帧号为奇数**时走 1 格，新列 = 当前列 + 方向；若新列越界，本帧**原地掉头**（方向取反、位置不动）。
6. **投弹**：**帧号 % 4 == 2** 时，在 `(坦克行 + 1, 坦克列)` 生成一颗炸弹。
7. **炸弹推进**：每颗炸弹行号加 1。
   - 新位置与玩家**同行同列** → 命中：炸弹消失、`LIVES -= 1`、`SCORE = max(0, SCORE - 20)`、`TAKEN += 1`。
   - 行号 ≥ H → 落出底部，消失。
8. **结束判定**：`LIVES` 变成 0 后，**本帧画面照常输出**，游戏立即结束——后面即使还有按键也**不再处理、不再输出任何帧**。

子弹与炸弹**互不影响**：子弹不会打掉炸弹，炸弹也不会挡住子弹。

## 渲染

一帧的 8 步做完后，把当前所有对象画到 H×W 的画布上，**后画的覆盖先画的**：

1. 炸弹 `*`
2. 子弹 `^`（多颗子弹在同一格也只画一个 `^`）
3. 坦克 `T`
4. 玩家 `M`

然后逐行输出，**行尾空格不要输出**（行首空格要保留；整行没有字符就输出一个空行）。

## 输入格式

- 第 1 行三个整数 `H W F`。
- 接下来 F 行，每行一个字符，依次是第 0 帧到第 F-1 帧按下的键（`a` / `d` / `s` / `.`）。

## 输出格式

- 每帧输出 H 行画面，共 F 帧（提前结束则更少），帧与帧之间不空行。
- 最后一行为结算：
  `SCORE <分数> HITS <命中次数> KILLS <击毁次数> TAKEN <被砸中次数> LIVES <剩余生命>`

## 提交要求

- 提交**多文件工程**：至少包含 `makefile` 与源码；平台在提交目录执行 `make shooter`，产物必须是可执行文件 `shooter`。
- 参考实现的结构（可以照抄这个分层）：
  - `Entity.h`：抽象基类，纯虚 `update(Game&)` / `symbol()`，**虚析构**；
  - `Entities.h/.C`：`Player` / `Tank` / `Bullet` / `Bomb`；
  - `Game.h/.C`：棋盘、容器、每帧 8 步、渲染、结算；
  - `main.C`：读入 → 逐帧驱动 → 打印结算。
- 场上对象会不断创建和销毁，必须用**基类指针 + 虚函数**统一管理（`list<Entity*>` 或 `vector<Entity*>` 都行），删除时不能漏掉派生类的析构。
- **不要** `#include <ncurses.h>`、**不要**链接 `-lncurses`、**不要**用 `getch()` / `mvaddch()` 这类终端函数——判题机上没有终端，`initscr()` 会直接失败。输入用 `cin`，输出用 `cout`。
- 本地怎么跑：`make shooter && ./shooter < 1.in`（重定向输入即可，和普通 OI 题一样），不需要打开交互界面。

## 样例说明

- **样例 1**（按键序列 `. d . a .`）：只有移动。玩家 `(4,6)` 右移到第 7 列，第 1 帧坦克也按"奇数帧走一格"挪到第 7 列；第 2 帧坦克在 `(2,7)` 投下炸弹，炸弹一路下落到第 5 行——玩家当时在第 6 列，所以没有受伤。
- **样例 2**（`s . . . .`）：第 0 帧开火，子弹生成在玩家头顶 `(3,6)`，本帧先升到 `(2,6)`；第 1 帧子弹升到 `(1,6)` 与坦克同格 → 命中 +10；紧接着结算击毁 +50，坦克重生回 `(1,6)`，再按"奇数帧移动"走到第 7 列。所以 `SCORE 60 HITS 1 KILLS 1`。
- **样例 3**（`s s s . s .`）：第 0 帧开火后冷却变成 3；第 1、2 帧再按 `s` 都被冷却挡掉（画面上不会出现新子弹）；第 3 帧冷却归零但按的是 `.`；直到**第 4 帧**才打出第二颗，第 5 帧它升到第 1 行。
- **样例 4**（`d . . . .`）：玩家先右移到第 7 列；第 1 帧坦克也走到第 7 列；第 2 帧坦克在 `(2,7)` 投弹；炸弹第 3 帧到 `(3,7)`，第 4 帧正好砸在 `(4,7)` 的玩家身上 → `LIVES` 3→2、`TAKEN` 1。此时分数还是 0，`max(0, 0-20)` 仍是 0。

## 分步提示

> 这题规则多，一次写完基本不可能。**建议按下面的顺序做，每一步都能单独验证**。

### 提示 1：先把画面立起来（不写任何交互）

只做三件事：读 `H W F`、在 `(H-2, W/2)` 画一个 `M`、在 `(1, W/2)` 画一个 `T`，每帧原样输出 H 行。
拿样例 1 的**第一帧**对一下：第 0 行空、第 1 行第 6 列是 `T`、第 4 行第 6 列是 `M`，其余行空。这一步过了，坐标系统就对了。

### 提示 2：想清楚"一帧"是什么，再拆类

`Game::tick(key)` 就是"跑一帧"，里面是题面那 8 步。类的关系建议这样：

- `Entity`（抽象基类）：`int row, col;` + `virtual void update(Game&) = 0;` + `virtual char symbol() const = 0;` + `virtual ~Entity() {}`；
- `Player` / `Tank` / `Bullet` / `Bomb`：只关心"我怎么动、我是什么字符"；
- `Game`：持有 `Player*`、`Tank*`、`list<Entity*> bullets_`、`list<Entity*> bombs_`，并对外提供 `playerRow()`、`tankCol()`、`tryFire()`、`onBulletHitTank()` 这类接口。

**为什么要基类指针**：子弹和炸弹会不停 `new` / `delete`，用 `list<Entity*>` 才能一条循环同时处理两种对象；删除时必须 `delete` 基类指针，所以基类要有**虚析构**，否则派生类的析构不会被调用。

### 提示 3：8 步的顺序不能乱

最容易错的是"谁先动"。记住三句话：

- **子弹先动、坦克后动**：所以子弹能打中"这一帧还没挪走"的坦克；
- **坦克先动、再投弹**：炸弹从坦克移动后的列掉下来；
- **炸弹最后动**：所以炸弹永远追不上刚移动过的玩家。

伪代码：

```cpp
void Game::tick(char key) {
    if (cooldown > 0) --cooldown;
    player->update(*this);                 // 移动 / 开火
    for (auto it = bullets.begin(); it != bullets.end(); ) {
        (*it)->update(*this);              // 行号-1，可能命中
        if ((*it)->dead()) { delete *it; it = bullets.erase(it); } else ++it;
    }
    if (tank->hp() <= 0) { tank->reset(W); score += 50; ++kills; }
    tank->update(*this);                   // 奇数帧走一格
    if (frame % 4 == 2) bombs.push_back(new Bomb(tank->row + 1, tank->col));
    for (auto it = bombs.begin(); it != bombs.end(); ) {
        (*it)->update(*this);
        if ((*it)->dead()) { delete *it; it = bombs.erase(it); } else ++it;
    }
    if (player->lives() <= 0) over = true;
    render();                              // 先画后 ++frame
    ++frame;
}
```

### 提示 4：几个"差一格"的地方

- **行号向下增大**：子弹是 `--row`，炸弹是 `++row`；玩家在 `H-2` 行（不是 `H-1`：最底下一行留给"炸弹落空"）。
- **命中判定用"移动后的位置"**：先 `row--`，再看是否与坦克同格；不要拿移动前的位置判。
- **坦克移动只在奇数帧**：`frame % 2 == 1`；第 0 帧不动，别写成"每帧都动"。
- **撞墙是原地掉头**：新列越界时只把方向取反，位置不变；不要"反弹并前进一格"，否则会跳过边界列。
- **冷却的边界**：第 0 帧开火 → 冷却 3；第 1 帧减到 2、第 2 帧减到 1、第 3 帧减到 0，所以**第 3 帧就能再开火**，间隔正好 3 帧。
- **行尾空格**：`cout << string(W,' ')` 整行输出会带着一堆空格，判题会因为行尾空格与你以为的"看起来一样"而判错——输出前把行尾空格截掉。
- **提前结束**：`LIVES` 归零的那一帧要照常输出画面，然后 `break`；不要把剩余帧也打印出来。

### 提示 5：怎么自测

1. 先只跑**一帧**（`F=1`），把画面和样例 1 的第 1 屏逐字符对一遍；
2. 再跑样例 1 的全部 5 帧，把输出存成文件，和题面样例用 `diff` 比；
3. 样例 2、3、4 分别验证"命中/击毁""冷却""受伤"三条支线；
4. 最后自己造一组 `H=12 W=30 F=200` 的数据看会不会崩（越界、空链表遍历时 `erase` 后迭代器失效是最常见的崩溃点）。

### 提示 6：如果判定 RE / WA，按这个顺序查

| 现象 | 先查什么 |
|---|---|
| 段错误 / RE | `erase` 之后还在 `++it`；基类没有虚析构导致 `delete` 出错；空链表被解引用 |
| 画面整体偏移一行或一列 | 初始位置写成 `(H-1, W/2)` 或 `((H-2), W/2+1)`；行号方向搞反 |
| 某一帧开始全错 | 8 步顺序错了（最常见：先移动坦克再推进子弹） |
| 只有最后一两帧错 | 提前结束没 `break`，或多输出了一帧 |
| 差一两个字符 | 行尾空格没截、覆盖顺序错（比如先画坦克再画炸弹） |

## 数据范围

- 6 ≤ H ≤ 12，13 ≤ W ≤ 30，1 ≤ F ≤ 200
- 保证子弹生成时不会与坦克重叠（玩家在 `H-2` 行、坦克在第 1 行，只要 H ≥ 5 就天然成立）
- 输出总行数不超过 `H × F + 1`

## 常见错误

1. **坦克每帧都动**：忘了 `frame % 2 == 1`，第 0、2、4 帧也走了一格。
2. **子弹先判命中再移动**：拿旧位置比较，永远打不中。
3. **击毁后不重置位置**：坦克停在原地，下一颗子弹又"命中"一次。
4. **炸弹从坦克移动前的列生成**：先 `addBomb` 再 `tank.update`，炸弹列会差一格。
5. **冷却按"帧数"算错**：把冷却写成 4 或把递减放到帧末尾，射速就慢/快一帧。
6. **撞墙时"反弹并前进"**：坦克会跳过最边上那一列。
7. **输出整行 W 个字符**：行尾一堆空格，判题判 WA/PE。
8. **`LIVES` 归零后继续输出**：多出的帧全部对不上。
9. **`delete` 基类指针但基类没有虚析构**：派生类成员没释放（本题不查内存，但工程习惯要养成）。
