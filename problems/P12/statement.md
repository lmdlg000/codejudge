# P12 货架巡检

> 难度：简单 · 单文件提交（main.cpp） · 构建：g++ -O2 -std=c++17 · 时限 1000ms / 256MB

## 题目背景

仓库的货架是 R 行 C 列的方格，第 i 行第 j 列叠放着 `a[i][j]` 件货物。巡检机器人从左上角 (1,1) 出发，按**顺时针回型**的固定路线走：

1. 把当前还没走过的矩形的最上面一行，从左走到右；
2. 沿最右一列往下走；
3. 沿最下一行从右往左走；
4. 沿最左一列往上走。

走完这一圈后，外圈的四条边已经清点完毕，机器人把外圈整体收缩掉，对里面剩下的矩形重复这四个动作，直到所有格子都走过。

机器人每进入一格花 1 个单位时间（起点那一格也算），同时清点该格货物。现在只批了 T 个单位的巡检预算，时间一到立即停下。请报告停下那一刻的进度：一共巡检了多少格、清点了多少件货物。

本题考查：输入输出、二维数组、四段循环与边界收缩、在预算内提前结束、累加时留意数据范围。

## 输入格式

- 第 1 行三个整数 `R C T`，用空格分隔。
- 接下来 R 行，每行 C 个非负整数，表示该格的货物件数。

## 输出格式

一行两个整数，用一个空格分隔：已巡检的格数、已清点的货物总件数。

## 提交要求

- 提交**单个源文件** `main.cpp`（C++），由平台执行 `g++ -O2 -std=c++17 -o {bin} {src}` 构建。
- 程序从标准输入读取数据、向标准输出写出结果；调试信息不得写入 stdout，`stderr` 评测忽略。

## 样例说明

- **样例 1**：只有一格，进入即花费 1，巡检 1 格、5 件。
- **样例 2**：2 行 3 列，回型顺序是 (1,1)(1,2)(1,3)(2,3)(2,2)(2,1)，预算 6 正好走完，货物合计 1+2+3+6+5+4=21。
- **样例 3**：3 行 3 列，回型顺序为 1、2、3、6、9、8、7、4、5，预算 4 只能走到第 4 格（值 6），格数 4、合计 12。
- **样例 4**：预算 100 远大于 12 格，走完就停：格数 12、合计 1+2+…+12=78。**预算用不完不是错误**。
- **样例 5**：只有一列时，回型的第一段就吃掉了这一列，预算 3 只够走三格，合计 10+20+30=60。

## 实现提示

**先想清楚"走完一圈"是什么意思**：用 `top`、`bottom`、`left`、`right` 四个变量框住"还没巡检的矩形"，初始为 `0, R-1, 0, C-1`。每走完一条边，就把那条边从矩形里去掉（`top++` / `right--` / `bottom--` / `left++`），下一条边自然从还没走到的格子开始。

**四段循环的骨架**：

```cpp
while (top <= bottom && left <= right && cnt < T) {
    for (int j = left; j <= right && cnt < T; j++) { /* a[top][j] */ }
    top++;
    for (int i = top; i <= bottom && cnt < T; i++) { /* a[i][right] */ }
    right--;
    if (top <= bottom) { for (...) { /* 下边，从右往左 */ } bottom--; }
    if (left <= right) { for (...) { /* 左边，从下往上 */ } left++; }
}
```

**分步算法（6 步）**：

1. 读入 `R C T`，再读满整个 R×C 矩阵；
2. 初始化四条边与两个计数器：`cnt`（已巡检格数）、`sum`（已清点件数）；
3. 外层 `while` 同时守住两件事：矩形还没走空、预算还没用完；
4. 依次写四段 `for`：上边向右、右边向下、下边向左、左边向上；每段循环条件都追加 `&& cnt < T`；
5. 每写完一条边立刻收缩它，**后两段收缩前要判断剩下的区域是否还存在**；
6. 输出 `cnt` 与 `sum`。

**关键边界与易错点**：

- **只剩一行或一列时会重复巡检**：走完上边后如果 `top > bottom`，下边那条线已经不存在了，第三段必须先判 `if (top <= bottom)`；第四段同理判 `if (left <= right)`。用 1 行 4 列、4 行 1 列亲手走一遍就能暴露这个错误。
- **预算是"进入格子"才扣**：起点也计 1，所以 `cnt` 从 0 开始、每进入一格先累加再判断是否到 T。
- **累加要用 `long long`**：R×C 最大 10⁶、单格最大 1000，总量可达 10⁹，`int` 在有的写法里会溢出。
- **`T` 本身很大**：T 可到 10⁹，别拿 T 当循环上限去跑，判断条件是 `cnt < T`。

## 数据范围

- 1 ≤ R, C ≤ 1000，且 R×C ≤ 10⁶
- 0 ≤ `a[i][j]` ≤ 1000
- 1 ≤ T ≤ 10⁹
- 巡检格数不超过 R×C；货物总数不超过 10⁹，用 `long long` 保存最稳妥

## 常见错误

1. **四段循环没有收缩边界**：走完上边不 `top++`，第二轮又走一遍上边，格数比预期多。
2. **第三、四段漏写 `if` 判断**：1 行 N 列的数据会在"下边"里把同一行再走一遍，答案偏大。
3. **把 `T` 当循环变量**：`for (int k = 0; k < T; k++)` 在 T=10⁹ 时直接超时——预算是"停止条件"，不是"循环次数"。
4. **只在四段之间检查预算**：一段 `for` 内部走完才看 `cnt < T`，会多巡检好几格，必须把守卫写进每段循环条件里。
5. **货物总数用 `int`**：10⁶ 格 × 1000 件会溢出，答案变成负数。
6. **输出顺序写反**：先格数、再件数，中间一个空格，行末不要多余空格。
